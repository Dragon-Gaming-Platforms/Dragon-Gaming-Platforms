# Thumbnail-Assets

Companion asset repository for
[Dragon-Gaming-Platforms](https://github.com/Dragon-Gaming-Platforms/Dragon-Gaming-Platforms).
It holds the platform's game-card artwork **outside** the main repository so the
main site stays under its 1 GB GitHub Pages budget, and it gets its own
independent 1 GB Pages budget.

Published at: `https://dragon-gaming-platforms.github.io/Thumbnail-Assets/`

## File structure

```
Thumbnail-Assets/
├── .github/
│   └── workflows/
│       └── build-thumbnails.yml   # push[main] + dispatch: validate -> convert -> commit -> deploy
├── thumbnails/
│   ├── <slug>.png|.jpg|.jpeg|.webp|.svg|.gif   # DROP ZONE: flat, one file per game
│   ├── README.md                  # drop-zone rules for contributors
│   └── jpg/                       # GENERATED by CI - do not edit by hand
│       ├── .gitkeep               # keeps this directory in Git before the first build
│       └── <slug>.jpg             # 800x260 JPEG, <=40 KB (animated sources stay .gif)
├── .gitignore
├── .nojekyll
└── README.md                      # this file
```

`<slug>` is **exactly the game's catalog `id`** in the platform repo (e.g.
`space-cadet-pinball.png`, `vectoid-td-3d-v1.4.png`). Display names are never
used: two games' normalized names collide with other games' ids, so id-only
matching is the only safe rule.

## Pipeline

1. You drop `thumbnails/<slug>.<ext>` and push to `main`.
2. `build-thumbnails.yml` scans the flat drop zone (files directly in
   `thumbnails/` only), picks one source per slug using the precedence
   `svg > png > webp > jpg > jpeg > gif`, and warns on duplicates.
3. Raster sources are cover-cropped to **800x260** and optimized down a quality
   ladder until they fit **<=40 KB**; SVGs are rasterized first via
   `rsvg-convert`, falling back to `svglib`, `cairosvg`, then ImageMagick.
   Transparency is flattened onto the site background `#09090f`.
   Animated `.gif` sources are copied through unchanged (JPEG cannot animate).
4. Results are written to `thumbnails/jpg/`, stale derivatives whose source
   disappeared are pruned, and the set is committed as `github-actions[bot]`
   (a GITHUB_TOKEN push, so it cannot retrigger this workflow).
5. The tree is published to GitHub Pages, giving stable URLs like
   `https://dragon-gaming-platforms.github.io/Thumbnail-Assets/thumbnails/jpg/<slug>.jpg`.
6. The platform repo's `sync-thumbnails.yml` (manual dispatch + nightly cron)
   reads that published set and writes the matching `"image"` field into
   `games.js`, `cdn.games.js` and `singlefile.html`.

## Rules for art

- Only artwork you have the right to display: your own renders/builds, official
  screenshots of permissively licensed games, or freely licensed art.
- No logos or trademarked characters you do not have rights to.
- Landscape art near 3:1 crops best; anything else is center-cover-cropped.
- Keep sources under ~5 MB; the published JPEG is always <=40 KB regardless.
- Git LFS is forbidden (Pages does not serve LFS files); GitHub's 100 MB
  per-file cap applies.
